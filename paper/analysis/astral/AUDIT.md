# Orbitrap Astral validation audit

## Editorial conclusion

The Astral result is technically coherent and survives the focused fairness
checks. It supports a narrow claim: on three independent 10 ng HeLa files from
PXD066701, using identical biosaur2 features, database, digest, and a common
entrapment scorer, uno substantially outperformed ms1searchpy. It does **not**
establish superiority on all Orbitrap Astral methods or samples.

The result should remain provisional until the searches are repeated from
archived, committed builds. The measured uno binary and ms1searchpy source came
from dirty working trees; hashes and diffs were captured, but that is weaker
provenance than a tagged release.

## Integrity checks

- All three raw files match the PRIDE-deposited byte sizes and have local
  SHA-256 hashes.
- ThermoRawFileParser 1.4.5 completed every conversion with zero errors and
  zero warnings.
- biosaur2 0.2.28 skipped no MS1 scans, detected the expected fixed FAIMS CV
  (-45 V), and produced 85,274, 88,845, and 90,376 features.
- Both engines searched the same feature table and human-plus-yeast FASTA with
  the same peptide-length, missed-cleavage, and fixed-modification settings.
- All 3 uno searches and all 30 serialized ms1searchpy searches exited 0 and
  produced complete protein tables.
- Independent pilot and production uno outputs for Astral 1 are byte-identical
  (SHA-256 `469cd93c...`).
- Entrapment scoring used the same deterministic, entrapment-first tie rule for
  both engines.

## Result

| File | uno @1% | ms1searchpy median (range) @1% | uno @5% | ms1searchpy median (range) @5% | median speed-up | memory ratio |
|---|---:|---:|---:|---:|---:|---:|
| Astral 1 | 1,448 | 45 (26–110) | 2,145 | 45 (26–151) | 10.1× | 2.3× |
| Astral 2 | 1,182 | 47 (30–105) | 1,685 | 47 (30–289) | 9.9× | 2.5× |
| Astral 3 | 1,006 | 46 (22–91) | 1,567 | 74.5 (22–113) | 9.5× | 2.0× |

Speed-up is the median ms1searchpy wall time divided by uno wall time. Memory
ratio is median ms1searchpy peak RSS divided by uno peak RSS.

## Why ms1searchpy is shallow here

The searches did not fail. ms1searchpy found only 5–14 proteins in its initial
stage in the representative production runs, invoked its low-identification
calibration fallback, and fitted RT standard deviations of approximately
1.7–2.3 min on an 11.4 min acquisition. Final internally reported protein
counts consequently remained low. The ten repeats per file show that random
decoy generation changes the exact result but not its order of magnitude.

Two controls on Astral 1 address the main fairness concerns:

- **Stock-equivalent feature columns + DeepLC:** removing the two locally added
  isotope-quality columns gave 36 proteins at both 1% and 5% entrapment FDR,
  inside the production range. The patch therefore did not create uno's lead;
  if anything, it gave ms1searchpy additional information.
- **Stock-equivalent columns + default ms1searchpy RT model:** disabling DeepLC
  gave 26 proteins at both thresholds. Optional DeepLC was therefore not an
  accidental handicap.

No broader parameter sweep is justified. Searching for a configuration after
seeing the answer would turn an external validation into post hoc tuning.
