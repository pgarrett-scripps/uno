# `analysis/` — the code behind the manuscript's figures

This directory produces every figure `paper.typ` and `si-body.typ` embed. It
writes **directly** into `../figures/`, with no staging copy, because a copy is
the single most reliable way for a manuscript to go quietly wrong: re-run the
analysis, forget to copy, and the PDF keeps rendering a plot that no longer
matches the numbers in its own caption.

**The contract with the manuscript is one recipe.** `just assets` (run from
`paper/`) delegates here and knows nothing else about this directory. Everything
below is this project's business.

| Command (from `analysis/`) | Does |
|---|---|
| `just assets` | The contract: tables, then figures. What `paper/`'s `just assets` calls |
| `just figures` | Regenerate only figures whose script or `style.py` is newer than the PNG |
| `just figures-all` | Regenerate every figure. Use after re-running a benchmark |
| `just tables` | No-op today; see "Tables" below |
| `just clean` | Delete `../figures/*.png` and `*.pdf` (they are tracked, so `git checkout` is usually better) |

## Figures

One script per figure, named for its output: `scripts/fig2_headtohead.py` writes
`../figures/fig2_headtohead.{png,pdf}`. That mapping is the wiring — a new
figure needs nothing added to the justfile, it just has to match `fig*.py`.
`paper/FIGURE_MANIFEST.md` is the index of filenames, panel contents and data
provenance.

Two files in `scripts/` are imported, not run, and are skipped by the globs:

- `style.py` — shared rcParams, the Wong colorblind-safe palette, ACS column
  widths, and `save()`. Import it *before* creating any figure; the rcParams are
  applied at import time. It also defines the paths (`PAPER`, `REPO`, `FIGDIR`,
  `FIGDATA`, `BENCH`) every script uses, all derived from `__file__`, so moving
  this directory moves them together.
- `entrapment_data.py` — the shared entrapment scorer that Figures 4, S1 and the
  SI tables read.

### Staleness is judged on the code, not the data

`just figures` compares the PNG's mtime against the script and `style.py` only.
The benchmark output these scripts read lives **outside the repo** (under
`/mnt/labdata/`, and `../../benchmark/`), is regenerated by hand, and its mtime
is never consulted. So after re-running a benchmark, use `just figures-all`.

`paper/just check-assets` closes the other half of the gap: it compares a content
stamp of this whole directory against `.assets-stamp`, written when `just assets`
last ran, so editing a generator and forgetting to run it is reported rather than
shipped.

### matplotlib is pinned

`pyproject.toml` pins `matplotlib==3.11.0`. The figures are tracked build
artifacts compared by content, and a minor matplotlib bump moves text metrics and
PNG bytes across every figure, which reads as real drift. Set
`metadata={"Software": None}` on `savefig` and seed any RNG for the same reason.

## Tables

`../si/*.typ` are currently **hand-transcribed** from benchmark output, and two of
them carry a "GENERATED … do not edit by hand" header that no script on disk
produces — see `paper/SUBMISSION_TODO.md` item D1, which is either to write the
generator or to correct the label.

When those generators are written, they go in `scripts/` as `gen_*_table.py`,
write a bare `#table(...)` into `../../si/` with no caption or label, and are
picked up by `just tables` with no further wiring. The caption and label live in
`si-body.typ`, which wraps the bare table in a `#figure`.

## Environment

Its own uv environment, separate from the manuscript toolchain in
`../pyproject.toml`: the toolchain is the same for every paper built on this
scaffold and stays locked, while these dependencies change with the science.
`just assets` builds it on demand; nothing here should be run with a bare
`python3`.
